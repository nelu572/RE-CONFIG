# ROOM Map Guide

## 목적

이 문서는 ROOM 타일맵 문서에서 공통으로 사용하는 규격, 범례, 표기 방식, 코드 반영 원칙을 정의한다. 전체 문서의 책임 분리는 [문서 책임 가이드](../DOCUMENTATION_GUIDE.md)를, 전반적인 구현 변경·상충 요청 처리 절차는 [구현 변경 규칙](../IMPLEMENTATION_RULES.md)을 따른다.

ROOM별 문서는 이 공용 맵 규칙을 반복하지 않는다. 공간 구조, 실제 배치, 구간별 의도, 풀이 흐름, 방별 예외만 기록하며, 적·피스톤·박스 등 공통 기믹의 동작·충돌·시각·기본 수치는 해당 공용 기믹 문서에 둔다.

## 공통 맵 규격

- 1T = 40px
- 각 ROOM의 전체 프레임 크기는 실제 코드의 RoomDef.bounds를 기준으로 적는다.
- 모든 ASCII 타일맵 행은 문서에 선언된 가로 글자 수와 일치해야 한다.
- 전체 행 수는 문서에 선언된 세로 타일 수와 일치해야 한다.
- ASCII 맵의 문자 하나는 반드시 1T × 1T 타일 하나만 뜻한다. 두 문자(`.=`, `#|` 등)를 이어 하나의 소수 좌표·부분 타일을 만들지 않는다.
- 선언 규격과 실제 ASCII 타일맵의 행/열 수가 다르면, 실제 타일맵 형태를 기준으로 전체 프레임/각 행 글자 수/전체 행 수 값을 갱신한다.
- 빈 공간은 `.`으로 적는다.
- 화면 밖이나 사용하지 않는 공간도 맵 안에서는 `#`로 채운다.
- ROOM마다 너비가 다를 수 있으므로 모든 ROOM을 48x27로 통일하지 않는다.

## 공통 범례

- `#` : 1T를 꽉 채운 일반 벽 / 고정 플랫폼
- `=` : 타일 상단에 붙은 높이 `0.25T`의 가로 부분 블록
- `|` : 타일 왼쪽에 붙은 폭 `0.25T`의 세로 부분 블록
- `.` : 플레이 가능한 빈 공간
- `P` : 플레이어 시작 위치
- `E` : EXIT 배치 예약 영역
- `A` : BRICK WALL / TYPE A 벽
- `B` : 중력 영향을 받는 박스 시작 영역
- `Q` : 박스 생성 중심 앵커. B 영역 안에서 실제 박스의 중심 좌표를 직접 지정할 때 사용한다.
- `K` : 일반 스피커 본체 영역
- `k` : 미니 스피커 본체 영역
- `M1` / `M2` : 몬스터 생성 코드
- `M` : 위를 향하는 정적 가시 (`0°`)
- `N` : 아래를 향하는 정적 가시 (`180°`)
- `L` : 오른쪽을 향하는 정적 가시 (`90°`)
- `R` : 왼쪽을 향하는 정적 가시 (`270°`)
- `C` : 플레이어 접촉 시 활성화되는 체크포인트 영역
- `T` : 압력 스위치
- `H` : 닫힌 상태의 가로 이동 플랫폼 / 문
- `V` : 닫힌 상태의 세로 이동 플랫폼 / 문
- `h` : H의 완전 개방 위치 마커
- `v` : V의 완전 개방 위치 마커
- `X` : 연결 스위치에 따라 페이드하며, 알파가 정확히 1일 때만 충돌하는 압력 장벽
- `0`~`9` : 스위치·이동 문/플랫폼·압력 장벽의 좌상단 ID 타일
- `I` : 피스톤 수축 상태의 헤드/플레이트 위치. 새로 작성하거나 수정하는 문서에서는 피스톤 시작 위치 마커로 사용한다.
- `i` : 피스톤 완전 확장 상태의 헤드/플레이트 위치. `I`에서 `i`까지의 직선 구간을 피스톤 이동 범위로 해석한다.

ROOM별 문서의 `사용 오브젝트`에는 해당 ROOM에서 실제 사용하는 문자만 적는다.

## 오브젝트별 표기 방식

부분 블록도 문자 하나가 타일 하나를 차지한다. `=`·`|`는 위 범례에 정한 모양 그대로 해당 타일 안에서만 충돌한다. 인접한 `.`와 부분 블록은 각각 독립 타일이며, 각 타일 안의 빈 부분이 이어져 실제 통로 폭을 만든다. 두 문자를 묶어 새로운 기호나 소수 좌표로 해석하지 않는다. 그 외 비정형 충돌이 필요하면 새 기호와 타일 안의 모양을 이 가이드에 먼저 추가한다.

A는 현재 코드의 `type_a_walls`에 해당한다. TYPE A는 기존 벽돌 오브젝트이며 외형을 변경하지 않는다.

B는 현재 코드의 `GravityBoxDef` 시작 배치 예약 영역이다. 실제 박스의 공통 크기는 [중력 박스](../design/gravity_box.md)를 따른다. 연속된 B 영역 안에 Q가 없으면 실제 박스는 B 영역의 정중앙에 배치한다. Q가 있으면 Q 타일의 정중앙을 실제 박스의 중심으로 사용한다. Q는 단독 오브젝트가 아니라 B 영역의 앵커 마커이며, Q가 있는 타일도 B 예약 영역에 포함된 것으로 해석한다.

K/k는 현재 코드의 `SpeakerDevice` 본체 영역이다. K는 가로 5칸 × 세로 9칸, k는 가로 3칸 × 세로 5칸의 직사각형으로 채워 표시한다. 음파는 별도 타일로 표시하지 않는다. 공통 본체 크기와 음파 규칙은 [스피커와 음파](../design/speaker.md)를 따른다.

`M1`과 `M2`는 현재 코드의 `WalkerEnemyDef` 생성 코드다. 두 글자는 타입을 읽기 위한 하나의 배치 마커이며, 플랫폼이나 타일 충돌체가 아니다. `M1`은 [M1](../design/walker_enemy.md)을, `M2`는 [M2](../design/mm_enemy.md)를 생성한다. 숫자는 스위치·문 ID가 아니며, 실제 시작 충돌 사각형·이동 방향·속도는 ROOM별 오브젝트 메모에 기록한다.

`M`은 `M1`/`M2`와 달리 단독 한 글자로 읽는 [정적 가시](../design/static_spike.md) 마커다. `M`은 `0°`, `N`은 `180°`, `L`은 `90°`, `R`은 `270°` 가시를 만든다. 이 네 마커는 모두 1T × 1T 배치 칸 안에서 기본 가시의 폭 1T·높이 0.5T 충돌 범위를 만든다. 플랫폼 면에 붙일 수 있지만, 지지면 없이 허공에 배치해도 유효하다.

C는 현재 코드의 `RoomDef.checkpoints`에 해당한다. 각 `C` 한 글자가 비충돌 `1T × 1T` 활성화 영역을 나타내며, 가장 최근에 닿은 C가 리스폰 위치가 된다. 공통 동작과 시각 사양은 [체크포인트](../design/checkpoint.md)를 따른다.

T는 현재 코드의 `PressureSwitchDevice` 배치 마커다. 공통 활성화와 매립 배치 규칙은 [압력 스위치와 이동 문](../design/pressure_switch.md)을 따른다.
스위치는 연결된 `T`와 ID 숫자 타일이 차지하는 직사각형 그대로 만든다. 기본 가로 스위치는 `2T × 1T`이며 ID를 쓰면 `1T`처럼 왼쪽 `T`를 숫자로 바꾼다. 세로 스위치는 `1T × 2T`이며 ID를 쓰면 위칸을 숫자로, 아래칸을 `T`로 적는다. 예를 들어 세로 1번 스위치는 `1` 다음 줄의 `T`다.
모든 스위치는 플레이어, 중력 박스, 피스톤 플레이트, M1, M2가 누를 수 있다. 오브젝트별 전용 스위치 표기는 만들지 않는다.

### 기존 규칙과 상충하는 변경 요청 (필수)

- 이 가이드의 모든 규칙뿐 아니라 해당 ROOM 문서, 현재 코드, 확정된 디자인·아트·입력·물리 규칙에 적용한다.
- 사용자가 어떤 변경을 직접 지시했더라도, 기존 규칙을 깨거나 기본 상호작용·충돌·외형·퍼즐 흐름·성능 피드백을 바꾸면 즉시 구현하지 않는다.
- 먼저 기존 상태와 요청의 차이, 플레이에 미치는 영향, 유지안·변경안을 구체적으로 설명하고 “이 예외로 진행할까요?”라고 한 번 더 명시적으로 확인한다.
- 승인 전에는 코드만 선행 변경하거나, 퍼즐 우회 방지·편의·자연스러움 같은 구현자 판단으로 예외를 만들지 않는다.
- 승인된 예외는 이유·영향·적용 범위를 해당 ROOM 문서의 오브젝트 메모와 구현 시 주의사항에 함께 기록한다.
- 상세 절차와 예시는 [구현 변경 규칙](../IMPLEMENTATION_RULES.md)을 따른다.

H와 V는 현재 코드의 `PressurePlatformDevice`다. X도 같은 장치의 소거 상태를 사용하며 이동하지 않는다. 연결 스위치가 눌리면 페이드아웃하고, 해제되면 페이드인하며, 알파가 정확히 1일 때만 충돌한다. 대문자 `H`/`V`는 항상 닫힌 상태의 문/플랫폼 영역이며, 움직이는 문/플랫폼은 이 닫힌 상태에서 실제로 차지하는 영역을 직접 표시한다. `H`는 주로 `open_offset_x`, `V`는 주로 `open_offset_y`를 사용한다.

새 문서에서 열린 위치까지 명시하려면 피스톤과 같은 호환 확장 표기를 사용한다. `h`는 `H`의 완전 개방 위치, `v`는 `V`의 완전 개방 위치를 뜻하는 비충돌 목표 마커다. 각 대소문자 쌍은 같은 크기의 직사각형이어야 하고, `H/h`는 수평, `V/v`는 수직으로만 이동할 수 있다. `open_offset_x` 또는 `open_offset_y`는 닫힌 영역과 목표 마커 중심의 차이로 산출한다. h/v가 없는 문은 기본 개방 규칙을 적용한다. `H`는 닫힌 폭만큼 오른쪽으로, `V`는 닫힌 높이만큼 아래로 이동한다. 즉 `H`의 기본 `open_offset_x`는 `+rect.w`, `V`의 기본 `open_offset_y`는 `+rect.h`다.

스위치와 이동 문/플랫폼 또는 압력 장벽을 직접 연결할 때는 숫자 `0`~`9`를 해당 마커 사각형의 좌상단 `(0, 0)` 타일에 넣는다. 숫자는 그 자리에 있던 `T`·`H`·`V`·`h`·`v`·`X`를 대체하지만, 연결된 같은 마커 영역의 일부로 해석한다. 같은 숫자의 `T`와 `H`/`V`/`h`/`v`/`X`는 자동으로 연결된다. 따라서 `1T`, `1VV`, `1vv`, `1XX`는 같은 ID의 장치를 뜻하며, 한 스위치가 여러 문이나 장벽을 제어할 때는 각 조각 좌상단에도 같은 숫자를 쓴다.
같은 ID의 문이나 장벽이 여러 직사각형 조각으로 나뉘어도 된다. 각 숫자는 해당 조각의 좌상단 앵커이며, 조각은 위에서 아래·왼쪽에서 오른쪽 순서로 읽는다. 각 앵커에서는 이미 앞 조각에 배정된 칸과 다른 마커를 제외하고, 해당 `H`·`V`·`X` 타일로 만들 수 있는 최대 직사각형만 그 조각으로 배정한다. 이렇게 분리된 조각은 같은 ID의 스위치에 함께 연결한다. 숫자 ID를 사용하는 오브젝트는 숫자를 제외하고도 종류를 판별할 마커 타일을 하나 이상 남겨야 한다. 이 규칙은 한 글자당 한 타일 규격을 바꾸지 않으며, 숫자가 없는 기존 문서는 그대로 유효하다.

I/i는 현재 코드의 `PistonDevice`다. 새로 작성하거나 수정하는 ROOM 문서에서는 피스톤을 전체 면으로 빽빽하게 그리지 않고, 수축 상태 헤드 위치를 `I`, 완전 확장 상태 헤드 위치를 `i`로 표시한다. `I`와 `i`는 같은 크기의 직사각형이어야 하며, 두 영역의 중심을 이은 수평 또는 수직 직선이 피스톤 이동 방향이다. 대각선 이동은 사용하지 않는다.

피스톤의 충돌/압박 범위는 `I`와 `i` 사이의 직선 sweep 전체로 해석한다. 따라서 플레이어 시작 위치, 박스, 스위치, 문, EXIT 같은 다른 마커가 그 sweep 안에 있으면 실제 게임에서도 피스톤과 상호작용하거나 막힐 수 있는 배치로 본다. 박스나 플레이어가 피스톤에 밀리는 구조를 만들 때는 해당 오브젝트가 이 sweep 안에 들어가도록 배치한다.

피스톤의 공통 속도와 물리 상호작용은 [피스톤](../design/piston.md)을 따른다. travel, 시작 지연 시간(초), direction, 실제 크기는 ROOM별 배치 메모에 적는다.

기존 문서에 이미 작성된 연속 `I` 영역은 구 표기로 취급한다. 구 표기에서 `I`는 피스톤이 지나가는 전체 위험 범위를 뜻한다. 새 ROOM을 만들거나 기존 ROOM 맵을 다시 정리할 때는 구 표기 대신 `I/i` 시작-끝 표기를 사용한다.

## 작성 원칙

- 새로운 ROOM 문서 양식을 임의로 만들지 않고, 이 공용 가이드와 ROOM별 문서 구조를 따른다.
- 현재 코드에 이미 존재하는 ROOM은 현재 코드의 실제 맵을 먼저 읽고 그 구조를 MD로 옮긴다.
- 여러 타일 크기의 오브젝트는 실제 크기감을 확인할 수 있도록 여러 문자 칸으로 표현한다.
- 움직이는 문/플랫폼 등은 맵 안에서 차지하는 영역을 직접 표시한다.
- 음파처럼 실제 타일 구조가 아닌 효과는 맵에 억지로 타일로 표시하지 않고 별도로 설명한다.
- 오브젝트 문자는 플랫폼이 아니라 배치 마커로 해석한다.
- 피스톤은 가로/세로 폭을 문자 반복으로 정확히 그리려 하지 않는다. 기본 폭 5T를 전제로 `I`와 `i`의 위치 관계를 우선한다. 예외 크기만 ROOM별 오브젝트 메모에 적는다.

## 코드 반영 공통 메모

- 연속된 `#`는 코드 반영 시 가능한 한 큰 플랫폼 Rect로 병합한다.
- `P`, `E`, `A`, `B`, `Q`, `K`, `M1`, `M2`, `M`, `N`, `L`, `R`, `C`, `T`, `H`, `V`, `h`, `v`, `X`, `0`~`9`, `I`, `i`는 플랫폼이 아니라 오브젝트 배치 마커로 처리한다.
- B 영역에 Q가 없으면 해당 B 영역의 bounding rect 중앙에 실제 박스를 배치한다.
- B 영역에 Q가 있으면 Q 타일의 중앙을 실제 박스 중심으로 삼고, 박스 크기는 ROOM별 구현 메모를 따른다.
- `P`는 RoomDef의 플레이어 시작 위치로 만든다.
- `E`는 RoomDef.exit로 만든다.
- `I/i` 피스톤 표기에서는 `I`를 수축 상태 plate rect, `i`를 완전 확장 상태 plate rect로 보고 `PistonDevice.travel`을 산출한다.
- ROOM별 `코드 반영 메모`에는 공통 규칙이 아니라 해당 ROOM에서만 필요한 실제 구현 규칙을 기록한다.

## ROOM 맵 → 코드 갱신 절차 (필수)

사용자가 `ROOM_XX_MAP.md`를 수정하고 코드 갱신을 요청한 경우, 수정된 것으로 보이는 행이나 오브젝트만 추정해 반영하지 않는다. ASCII 타일맵 전체를 한 번의 입력으로 읽고, 아래 절차를 끝까지 수행한다.

### 1. 입력 맵 검증

1. `~~~text` 블록의 모든 행을 읽는다. 선언한 가로·세로와 행 수·각 행 길이가 일치하는지 먼저 확인한다.
2. 코드 배치 동기화의 좌표 기준은 ASCII 마커다. 규격/오브젝트 메모와 ASCII 마커가 다르면, ASCII 기준으로 코드만 갱신하고 메모는 수정하지 않는다. 이 불일치는 작업 완료 보고에 남긴다. ASCII 맵 자체가 선언 규격을 만족하지 않거나 마커 해석이 불가능할 때만 기준을 확인받는다.
3. `M1`/`M2`는 두 글자를 하나의 비충돌 생성 마커로 읽는다. 두 번째 글자의 `1`/`2`를 스위치 ID로 중복 해석하지 않는다.
4. `T`, `H`, `V`, `h`, `v`, `X` 앞의 숫자는 같은 장치의 좌상단 마커로 읽는다. 숫자만으로 새 스위치나 문을 만들지 않는다.

### 2. 전체 배치 추출

아래 항목을 **행 전체**에서 추출한다. 최근에 바뀐 것으로 보이는 하단·상단·주변 몇 줄만 읽고 반영해서는 안 된다.

- 모든 `#`의 좌표를 추출하고, 코드에서는 누락 없이 가능한 큰 `RectF`로 병합한다. 단독 `#`도 고정 지형이다.
- `P`, `E`, `C`, `A`, `B`/`Q`, `K`, 모든 `M1`/`M2`, 모든 정적 가시(`M`/`N`/`L`/`R`)의 좌표·직사각형을 추출한다.
- 모든 스위치와 연결 ID, `H`/`V`/`X`의 닫힌 사각형 및 `h`/`v`의 열린 목표를 추출한다.
- 모든 `I/i` 쌍의 크기·방향·수축/완전 확장 plate 위치를 추출한다.

### 3. 코드 대조와 반영

코드 수정 전후에 다음을 각각 대조한다.

| 대상 | 반드시 확인할 대응 코드 |
| --- | --- |
| `#` | `RoomDef.platforms` 전체. 맵에 없는 고정 지형과 누락된 단독 타일이 없어야 한다. |
| `P` / `E` / `C` | `RoomDef`의 시작 위치, exit, checkpoint |
| `A`, `B`/`Q`, `K` | TYPE A, 중력 박스, 스피커 배열 |
| `M1` / `M2` | 생성 코드, 시작 위치, ROOM별 속도·방향 메모 |
| `M` / `N` / `L` / `R` | `StaticSpikeDef`의 배치 좌표와 회전 |
| `T`와 ID | `PressureSwitchDevice`, 연결 mask, 매립면의 충돌체 |
| `H`/`V`/`X` | `PressurePlatformDevice`의 닫힌 rect, 열린 offset, 소거 상태 |
| `I/i` | `PistonDevice`의 폭, body/plate 위치, 방향, travel |

배치 마커는 고정 지형으로 변환하지 않는다. 반대로 `#`를 삭제·분할할 때는 그 자리에 놓인 스위치·문·박스·적 마커까지 함께 대조한다. 특히 바닥 매립형 스위치의 표면 칸은 고정 `#`와 겹치지 않으며, 바로 아래 행부터 고정 바닥이 이어져야 한다.

### 4. 확장 물리 검증

이 항목은 ROOM 전체 구현 또는 사용자가 실제 플레이·물리 검증을 요청한 경우에 수행한다. 짧은 코드 동기화 요청의 필수 검사는 저장소 AGENTS.md의 ROOM 맵 코드 갱신 단축 요청을 따른다.

반영 뒤에는 최소한 다음을 확인한다.

- 모든 피스톤 sweep 안의 고정 지형·마커 충돌 여부와 I/i travel 일치
- H/h, V/v 이동 경로의 고정 지형 충돌 여부
- P, C, E, 박스, M1/M2 시작 위치가 의도하지 않은 고정 지형 또는 닫힌 문과 겹치지 않는지
