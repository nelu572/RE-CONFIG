# ROOM Map Guide

## 목적

이 문서는 ROOM 타일맵 문서에서 공통으로 사용하는 규격, 범례, 표기 방식, 코드 반영 원칙을 정의한다.
ROOM별 문서는 이 공용 규칙을 반복하지 않고, 해당 ROOM의 목적, 실제 사용 오브젝트, 타일맵, 방별 구현 메모만 기록한다.

## 공통 맵 규격

- 1T = 40px
- 각 ROOM의 전체 프레임 크기는 실제 코드의 RoomDef.bounds를 기준으로 적는다.
- 모든 ASCII 타일맵 행은 문서에 선언된 가로 글자 수와 일치해야 한다.
- 전체 행 수는 문서에 선언된 세로 타일 수와 일치해야 한다.
- 선언 규격과 실제 ASCII 타일맵의 행/열 수가 다르면, 실제 타일맵 형태를 기준으로 전체 프레임/각 행 글자 수/전체 행 수 값을 갱신한다.
- 빈 공간은 `.`으로 적는다.
- 화면 밖이나 사용하지 않는 공간도 맵 안에서는 `#`로 채운다.
- ROOM마다 너비가 다를 수 있으므로 모든 ROOM을 48x27로 통일하지 않는다.

## 공통 범례

- `#` : 일반 벽 / 고정 플랫폼
- `.` : 플레이 가능한 빈 공간
- `P` : 플레이어 시작 위치
- `E` : EXIT 배치 예약 영역
- `A` : BRICK WALL / TYPE A 벽
- `B` : 중력 영향을 받는 박스 시작 영역
- `K` : 스피커 본체 영역
- `T` : 측면 스위치
- `H` : 스위치 작동 시 가로로 열리는 플랫폼 / 문
- `V` : 스위치 작동 시 세로로 열리는 플랫폼 / 문
- `I` : 피스톤 본체 및 플레이트 이동 범위

ROOM별 문서의 `사용 오브젝트`에는 해당 ROOM에서 실제 사용하는 문자만 적는다.

## 오브젝트별 표기 방식

A는 현재 코드의 `type_a_walls`에 해당한다. TYPE A는 기존 벽돌 오브젝트이며 외형을 변경하지 않는다.

B는 현재 코드의 `GravityBoxDef` 시작 영역이다. 여러 타일 크기의 박스는 실제 크기감을 확인할 수 있도록 여러 문자 칸으로 표현한다.

K는 현재 코드의 `SpeakerDevice` 본체 영역이다. 스피커는 실제 크기감을 보기 위해 K를 여러 칸으로 채워 표시한다. 음파는 별도 타일로 표시하지 않는다. 스피커는 360도 범위로 영향을 주므로, 맵에서는 K와 다른 오브젝트의 상대 위치만 보고 판단한다.

T는 현재 코드의 `PressureSwitchDevice`다. 스위치는 기본적으로 모든 물리 오브젝트가 누를 수 있는 `PRESSURE_SWITCH_ANY`를 사용한다. 단, 방 설계상 필요한 경우 예외 activator를 사용할 수 있다.

H와 V는 현재 코드의 `PressurePlatformDevice`다. 움직이는 문/플랫폼은 맵 안에서 실제로 차지하는 영역을 직접 표시한다. H는 `open_offset_x`, V는 `open_offset_y`를 사용하는 경우가 많다.

I는 현재 코드의 `PistonDevice`다. 피스톤은 실제 크기감을 보기 위해 본체와 플레이트가 움직이는 전체 범위를 I로 표시한다. 샤프트 폭이 더 얇더라도 맵에서는 플레이어가 위험 영역으로 인식해야 하는 범위를 우선한다.

## 작성 원칙

- 새로운 ROOM 문서 양식을 임의로 만들지 않고, 이 공용 가이드와 ROOM별 문서 구조를 따른다.
- 현재 코드에 이미 존재하는 ROOM은 현재 코드의 실제 맵을 먼저 읽고 그 구조를 MD로 옮긴다.
- 여러 타일 크기의 오브젝트는 실제 크기감을 확인할 수 있도록 여러 문자 칸으로 표현한다.
- 움직이는 문/플랫폼 등은 맵 안에서 차지하는 영역을 직접 표시한다.
- 음파처럼 실제 타일 구조가 아닌 효과는 맵에 억지로 타일로 표시하지 않고 별도로 설명한다.
- 오브젝트 문자는 플랫폼이 아니라 배치 마커로 해석한다.

## 코드 반영 공통 메모

- 연속된 `#`는 코드 반영 시 가능한 한 큰 플랫폼 Rect로 병합한다.
- `P`, `E`, `A`, `B`, `K`, `T`, `H`, `V`, `I`는 플랫폼이 아니라 오브젝트 배치 마커로 처리한다.
- `P`는 RoomDef의 플레이어 시작 위치로 만든다.
- `E`는 RoomDef.exit로 만든다.
- ROOM별 `코드 반영 메모`에는 공통 규칙이 아니라 해당 ROOM에서만 필요한 실제 구현 규칙을 기록한다.
