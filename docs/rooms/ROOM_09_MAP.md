# ROOM 09 Map Draft

## 방향

ROOM 09는 기존의 사각형 퍼즐룸이나 미로형 구조가 아니라,
**여러 높이의 플랫폼을 직접 점프로 이어 가는 플랫포머형 스테이지**로 설계한다.

이 방의 핵심은 새 몬스터를 설명문으로 가르치는 것이 아니라,
플레이 과정에서 다음 순서로 자연스럽게 이해시키는 것이다.

1. 갇힌 몬스터를 먼저 안전하게 관찰한다.
2. 몬스터 위의 플랫폼들을 점프로 넘어간다.
3. 일반 점프로는 닿지 않는 높이를 피스톤 점프로 올라간다.
4. 높은 플랫폼들을 따라 이동하면서 세로 이동감을 크게 준다.
5. 마지막에는 두 번째 몬스터의 이동/정지를 이용해 스위치를 누르게 한다.
6. 스위치로 열린 길을 통과해 EXIT에 들어간다.

이전 ROOM 09의 무채색 / 랜덤 컬러 / 미로 방향은 이 맵의 기준으로 사용하지 않는다.

---

## 맵 규격

- `1T = 40px`
- 전체 프레임: **96T x 27T**
- 전체 행 수: **27**
- 각 행 글자 수: **96**
- 가로 길이: 3840px
- 기준 화면 폭 48T보다 넓은 약 2화면 분량의 횡스크롤 구조
- 외곽을 네모 벽으로 완전히 감싸지 않는다.
- `#` 플랫폼 자체가 맵의 실루엣과 이동 경로를 만든다.
- 낙하 가능한 빈 공간을 적극적으로 사용한다.
- 일반 점프 구간의 주요 상승 높이는 약 `2T~3T`로 둔다.
- 피스톤 구간만 일반 점프로 바로 올라가기 어려운 높이 차를 사용한다.

---

## 범례

- `#` : 일반 고정 플랫폼 / 벽
- `.` : 빈 공간
- `P` : 플레이어 시작 위치
- `M` : 몬스터 배치 예약 영역
- `I` : 피스톤
- `T` : 몬스터가 누를 스위치
- `V` : 스위치 작동 중 열리는 통로 / 문
- `v` : V의 완전 개방 위치 마커
- `0`~`9` : 스위치·V 연결 ID의 좌상단 타일
- `E` : EXIT 배치 예약 영역

### 몬스터 `M`

- `M`은 **2T x 2T 예약 영역**으로 작성한다.
- 공통 동작·충돌·시각 사양은 [기본 이동형 적](../design/walker_enemy.md)을 따른다.
- ROOM 09에는 몬스터를 2마리 배치한다.

#### 첫 번째 몬스터
- 좌측 초반의 낮은 포켓에 갇혀 있다.
- 좌우 왕복만 하며 플레이어에게 바로 접근할 수 없다.
- 플레이어는 위쪽 플랫폼으로 넘어가면서 몬스터의 기본 움직임을 관찰한다.
- 이 몬스터는 학습용이며 퍼즐 정답에는 직접 사용하지 않는다.

#### 두 번째 몬스터
- 우측 마지막 구간의 낮은 통로에서 왕복한다.
- 플레이어는 몬스터가 `T` 위에 있을 때 가까이 접근해 정지 상태로 만든다.
- 몬스터가 스위치를 누르고 있는 동안 `V`가 열리고 EXIT로 갈 수 있다.

## 구간별 의도

### A. START / 몬스터 관찰

좌측 시작부는 플레이어가 움직이자마자 첫 번째 몬스터를 볼 수 있게 한다.

- 플레이어는 안전한 위쪽 발판에 있다.
- 몬스터는 아래 포켓에서 좌우로 왕복한다.
- 플레이어가 몬스터와 같은 바닥으로 내려갈 필요는 없다.
- 설명 텍스트 없이 움직임과 위험성을 먼저 보여준다.

핵심은 **몬스터 소개를 튜토리얼 UI가 아니라 공간 배치로 해결하는 것**이다.

### B. 기본 점프 구간

첫 몬스터 위를 지나간 뒤 여러 개의 독립 플랫폼을 연속으로 배치한다.

- 높이가 일정하지 않다.
- 상승 → 하강 → 상승을 섞는다.
- 모든 발판을 일렬로 나열하지 않는다.
- 정밀 점프보다는 이동 리듬이 느껴지는 간격을 우선한다.

ROOM 09가 기존의 '방 안 퍼즐'보다
**실제로 스테이지를 횡단하는 느낌**이 나야 한다.

### C. 피스톤 점프

중앙의 `I`는 아래 지대에서 높은 플랫폼으로 올려 보내는 용도다.

- 일반 점프로 바로 높은 플랫폼에 도달하지 못하게 한다.
- 플레이어는 피스톤 타이밍을 보고 위쪽 경로로 올라간다.
- 피스톤 자체를 복잡한 퍼즐로 만들지 않는다.
- 목적은 플랫폼 이동의 높이 변화와 속도감을 크게 만드는 것이다.

### D. 상단 플랫폼 구간

피스톤 이후에는 화면 상단에 가까운 플랫폼들을 이동한다.

- ROOM 전체의 세로 폭을 실제로 사용한다.
- 앞 구간보다 낙하 높이가 커져 공간이 넓어 보이게 한다.
- 마지막 퍼즐 지역이 아래쪽에 보이기 시작하도록 카메라 구도를 잡을 수 있다.

### E. 몬스터 스위치 / EXIT

마지막 구간은 두 번째 몬스터가 낮은 통로에서 좌우로 왕복한다.

- `T`는 몬스터 이동 경로 안에 둔다.
- 플레이어가 직접 `T`를 눌러 해결할 수 없게 한다.
- 몬스터가 그냥 지나가기만 하면 충분하지 않고,
  플레이어가 가까이 접근해 몬스터를 `T` 위에서 멈추게 하는 것이 목표다.
- 몬스터가 웅크려 정지하면 스위치가 유지된다.
- `V`가 열리면 플레이어는 바로 옆의 EXIT 구간으로 넘어간다.

마지막 퍼즐의 핵심은:

**몬스터를 피하는 것 → 몬스터의 행동을 이용하는 것**

으로 역할을 전환시키는 것이다.

## 플레이 흐름

`START`
→ 갇힌 몬스터 관찰
→ 몬스터 위로 점프
→ 여러 독립 플랫폼 횡단
→ 피스톤 점프
→ 상단 플랫폼 이동
→ 마지막 몬스터 구간으로 내려옴
→ 몬스터를 스위치 위에서 웅크리게 함
→ `V` 개방
→ `EXIT`

---

## 구현 시 확인할 것

1. 첫 몬스터가 시작 위치에서 바로 시야에 들어오는지
2. 첫 점프 구간이 최대 점프 높이/수평 이동 거리 안에서 안정적인지
3. 피스톤을 사용하지 않고 높은 경로로 바로 올라갈 수 없는지
4. 상단 플랫폼에서 떨어졌을 때 의도치 않은 스킵 경로가 생기지 않는지
5. 마지막 몬스터의 정지 감지 거리가 스위치 퍼즐에 적절한지
6. 몬스터가 `T`를 단순 통과하는 것만으로 퍼즐이 너무 쉽게 풀리지 않는지
7. 플레이어가 직접 `T`를 눌러 우회할 수 없는지
8. `V`가 열린 동안 EXIT까지 이동할 시간이 충분한지
9. 96T 폭 카메라 이동이 기존 카메라 시스템에서 자연스럽게 동작하는지
10. 맵 외곽을 네모 벽으로 막지 않아도 낙하/리셋 처리가 정상적인지

## 현재 단계에서 고정하지 않는 것

- `V`의 실제 이동 거리
- 카메라 세부 트리거 위치
- 플랫폼 간격 1T 단위의 최종 튜닝

우선 이 타일맵으로 **공간 구조와 플레이 흐름을 구현한 뒤**,
실제 조작감에 맞춰 플랫폼 위치만 미세 조정한다.

## 코드 반영 조정

- 문서의 `#` 좌표를 그대로 고정 플랫폼으로 반영했다. 첫 번째 몬스터는 `y=25T` 바닥의 낮은 포켓에서 시작하며, 플레이어는 시작 바닥과 `x=19T` 발판을 통해 위쪽 점프 경로로 진입한다.
- 중앙 피스톤은 문서의 수축 `I`(23행)와 확장 `i`(15행)에 맞춰 `x=52T`에서 위로 `8T` 이동한다.
- 마지막 `2T`는 플레이어·박스·피스톤이 아닌 두 번째 이동형 몬스터만 누를 수 있다. 몬스터가 스위치 위에서 정지한 동안 `2VVVV`가 `2vvvv` 목표 위치로 위로 `5T` 이동해 EXIT 통로를 연다.
